# LeafSense - AI Plant Disease Detection System

LeafSense is a web-based application that uses artificial intelligence to detect plant diseases from uploaded images. The system analyzes leaf photos and returns a diagnosis including the disease name, severity level, treatment recommendations, and prevention advice. It was developed as a Final Year Project focused on applying deep learning to practical agricultural problems.

---

## Project Overview

The core idea is simple: a farmer or gardener takes a photo of a plant leaf, uploads it to the system, and within seconds receives a detailed report about whether the plant is healthy or diseased. If a disease is detected, the system explains what it is, how serious it is, and what steps to take.

The system supports six crops: Tomato, Potato, Corn, Apple, Grape, and Bell Pepper. Across these crops, it can identify 27 different conditions including diseases like Early Blight, Late Blight, Common Rust, Apple Scab, and Grape Black Rot, as well as healthy specimens.

## Technology Stack

**Frontend**
- HTML5, CSS3, JavaScript (vanilla)
- Firebase Authentication for user login and signup
- Firebase Firestore for storing user data
- 5 pages: Login, Home, Services, About, Recommendations, Dashboard

**Backend**
- Python 3.11
- Flask web framework
- Flask-CORS for handling cross-origin requests

**AI and Machine Learning**
- Groq API (primary) - LLaMA vision model for image analysis
- TensorFlow / Keras - local MobileNetV2 model as fallback
- MobileNetV2 architecture trained on PlantVillage dataset
- Transfer learning with two-phase training

**Dataset**
- PlantVillage dataset from Kaggle
- Approximately 54,000 plant images
- 38 disease classes in full dataset
- Filtered to 27 classes for this project

## Installation and Setup

### Step 1 - Clone or download the project files

Place all files in a single folder on your computer. This guide assumes the folder is at:

```
C:\Users\YourName\Desktop\Leaf sense\
```

### Step 2 - Install Python dependencies

Open a terminal in the project folder and run:

```
pip install -r requirements.txt
```

This installs Flask, TensorFlow, Pillow, and all other required packages. The process may take a few minutes depending on your internet speed.

### Step 3 - Configure the API key

Open App.py and find line 18. Replace the placeholder with your Groq API key:

```python
GROQ_API_KEY = "your_actual_api_key_here"
```

You can get a free API key from console.groq.com. The free tier allows 14,400 requests per day which is more than enough for development and demonstration purposes.

### Step 4 - Add the trained model

Place these two files in the project folder:

- plant_disease_model.h5
- class_names.json

These are generated by running train_model.py in Google Colab, or can be trained locally if you have the PlantVillage dataset available.

### Step 5 - Start the backend server

```
python App.py
```

When the server starts successfully, you will see output similar to this:

```
LeafSense AI Backend v7.0
Groq Vision ready
Local model loaded
API running at http://127.0.0.1:5000
```

### Step 6 - Open the frontend

Open the project folder in VS Code, click on index.html, and click the Go Live button at the bottom right. The website opens in your browser at http://127.0.0.1:5500/index.html.

## How the AI Detection Works

When a user uploads an image, the following steps happen:

1. The JavaScript in main.js reads the image file selected by the user.
2. It sends a POST request to http://127.0.0.1:5000/api/detect with the image as form data.
3. The Flask server in App.py receives the image and passes it to the analyze_with_groq function.
4. The image is converted to base64 and sent to the Groq API along with a structured prompt.
5. Groq runs the LLaMA vision model on the image and returns a JSON response containing the disease name, confidence score, severity, description, treatment steps, and prevention advice.
6. If the Groq API fails for any reason, the system falls back to the local TensorFlow model.
7. The result is returned to the frontend as a JSON response.
8. JavaScript renders the result on screen and saves it to localStorage for the history feature.

## API Endpoints

The Flask backend exposes three endpoints:

**GET /**
Returns basic information about the running server including version and status.

**GET /api/health**
Returns the current health status of the server. Used by the frontend to check if the backend is online.

**POST /api/detect**
The main detection endpoint. Accepts an image as multipart form data or as a base64-encoded string in JSON. Returns a complete diagnosis report.

Example response:
```json
{
  "success": true,
  "mode": "groq_vision",
  "diagnosis": {
    "disease": "Tomato Early Blight",
    "crop": "Tomato",
    "confidence": 94,
    "severity": "Moderate",
    "description": "Caused by Alternaria solani...",
    "treatment": ["Apply chlorothalonil fungicide", "Remove infected leaves"],
    "prevention": "Rotate crops and stake plants for airflow"
  },
  "report_id": "LS-20240519143022"
}
```

**GET /api/diseases**
Returns the full list of supported diseases and crops.

## Model Training

The MobileNetV2 model was trained using Google Colab with a T4 GPU. Training was done in two phases:

Phase 1 used a frozen MobileNetV2 base pretrained on ImageNet, with a custom classification head added on top. The base layers were not updated in this phase, only the new layers were trained. This ran for up to 15 epochs with early stopping.

Phase 2 unfroze the last 30 layers of the base model and fine-tuned them at a very low learning rate of 0.00001. This ran for up to 10 epochs with early stopping.

The training used image augmentation including rotation, horizontal flipping, brightness variation, and zoom to prevent overfitting. Class weights were computed to handle imbalanced data across the 27 classes. Final validation accuracy reached approximately 93 percent.

## Authentication

The login and signup system uses Firebase Authentication. Three methods are supported: email and password, and Google OAuth. When a user signs up, their name, email, and profile photo are stored in Firebase Firestore under a users collection. When a user logs in, their information is also saved to localStorage so it can be accessed by other pages without additional database calls.

## Known Limitations

The model performs best on clear, close-up images of individual leaves with good lighting and a plain background. Performance may decrease on:

- Whole plant photos rather than leaf closeups
- Images with very dark or unusual lighting
- Photos of fruit rather than leaves
- Images taken at unusual angles

The system currently supports only the six crops listed above. Uploading an image of a different plant may result in an incorrect classification.
